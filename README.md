奇遇、秘境与迷雾共用修仙页，远征、农场、方舟避难所与模型股市共用另一页；包含随机点击延迟、动态农场收益比较和七日本地日志。

当前版本 **v1.14.38**：避难所调岗、穿衣、产出和奖励领取核对时，若当前快照时间早于原操作保存的快照，不会仅凭目标状态吻合就清除记录；保留原有只读预约，数据恢复后继续核对。面板与七日日志会说明快照时间落后；没有时间字段的旧记录仍沿用原规则。

相较v1.8.0，本次升级还包括：

- 避难所人员管理、闲置服装穿戴、满员岗位优化，以及受容量和供应约束的人口发展；人口目标默认14，已培养感情或待产的家庭保留原安排。
- 单人探险归来领取、建造/升级/扩容建议和运行提醒；建设、医疗、救援及小队操作仍由用户安排。
- 远征组中的股票买卖和涨跌预测，分别配置滚动24小时额度；预测固定单注，未配置额度和开关时不交易。
- 两页面板的折叠与版本显示，以及跨刷新、后台冻结、未决操作和跨标签页恢复的完善。

新增人员、生产、人口、探险领取和股市自动功能需在远征面板按需开启；配置方法见[使用说明](arkengine-auto-encounter-使用说明.md)。

保留v1.14.18避难所供应修复：普通调岗和原家庭轮换按离岗后的实际房间产量判断供应。额外驻留成人不被误扣产，离岗后有人接替时可以正常调配；两位家人一起离岗时按实际替补人数核对，替补不足仍保留供应。接替安排同时核对当前与未来产量；原家庭与新配对按安全顺序入住，刷新后接续剩余步骤。人口发展复用相同计算，外出、倒下、未成年和已预留离岗的居民不冒充替补。

保留v1.14.17股市发送保护：原生请求发出前再次核对共享状态。原生按钮触发后刚发生总暂停、额度或保留余额调整、新支出或人工持仓归属变化时，停止旧操作并保留原记录；买卖、预测及确认原交易均遵守此边界。

保留v1.14.16避难所请求保护：普通领取、奖励、调岗和穿衣核对原生请求地址、方法、正文、动作及目标；不匹配时停止并保留原记录。免费赛季的后续异步请求继续按原预留档位顺序核对，暂停后不继续发送，也不接受被改为付费或其他动作的请求。批次完成或失败后释放捕获，人工处理原结果后仍只核对，不重放已领取档位。

保留v1.14.15跨页同步修复：检查或修改人口目标时保留最新配对进度；别页暂停撤销尚未发出的领取。可读冲突一分钟后复查，损坏原文和未知操作继续保留。

旧响应迟到时也不覆盖已替换的原操作。记录损坏后能退出避难所；如果连暂停开关也保存失败，本页保持停止并显示修复提示，避免反复写入或被旧开启状态自动恢复。

保留v1.14.14股市同步修复：操作、保存设置和写入前核对最新预算、原请求及人工持仓归属；可读冲突预约五分钟后复查。两种玩法继续共用远征运行锁，同步检查不能替代跨进程原子事务。

保留v1.14.13的预测结算校验：损坏记录保留原文，避免被七天清理误删；合法结算正常处理，未结算记录仍保留。避难所保留床位与口粮统一规划、倒下居民恢复名额和原家庭保护。

保留v1.14.9的配对接续：新配对宿舍临时停电、发生事件或升级时，保留原计划与步骤；恢复后核对条件，两人均入住时重新给予30分钟等待。手动换人、拆房或接管窗口仍取消剩余安排，等待与恢复分别记录。

保留v1.14.8的读取恢复：避难所响应暂时截断或无法解析为JSON时，保留开关和原操作记录，返回远征并约15分钟后复查。数据恢复后先核对原结果，再继续工作，不重复提交未知操作。

保留v1.14.7的新买入成本核验：份额已显示但成本为0时，保留原交易与预留预算，刷新后仍核对同一笔，实际成本完整后再入账，不重复买入。

保留v1.14.6的扩仓规划：计入已开工工程完工后的容量，足以缓解当前满仓时先等现有工程，仍接近满仓则保留扩仓方案。扩容增量按前后总容量取整求差；未来容量仅用于建议，领取继续核对当前容量。

保留v1.14.5的完工后耗电预留，核对下一项扩建的电力余量与施工期间储备。工程完成后按当前需求重算，不重复预留；在建发电设施提示完工后按实际人员复核。建造、升级和下挖仍只提供建议。

保留v1.14.4的股市净到账保护。系统储备或单笔额度限制导致拆单后扣费取整为0代币时，保留持仓、显示原因并定时复查；储备或报价恢复后继续，不触发永久停止，也不阻塞其他符合条件的操作。

预测结算先保存账本，再记录完成日志。修复账本写入失败、刷新恢复后同一结算被重复记录的问题；返还仍不补回下注额度，也不计入本组毛收入。

保留v1.14.3的避难所生育心情门槛。新配对与原家庭返宿舍都要求双方心情至少50；排队、安排一半或准备接替生产岗位时会重新核对，条件变化则停止剩余安排。已确认的感情保持原安排，在运行提醒中说明暂停原因，心情恢复后继续检查。

修复长时间挂起后的配对恢复：两人都入住后才开始30分钟感情等待；只入住一人时继续核对剩余步骤，心情等条件变化时按取消处理，避免误加24小时失败限制。

发展建议也按网页的调岗容量核对空位：外出居民若仍登记在房间，不能将其位置当作可直接补员的空岗；产出与归来后的供应需求分别计算。

保留v1.14.2的在家伤员与求援提醒、股市和探险领取请求保护。自动操作遇到请求格式变化时在发送前停止并保留原记录；人工 Request 交易保持原请求与响应，也能处理正文观察迟到时的原交易回执。

保留v1.14.1的跨玩法恢复与迟到成交计时：暂停功能的原记录不阻塞其他玩法，等待其他功能时让出远征并预约复查，限次切页继续保留真实弹窗和账号保护。

保留v1.14.0的可选“自动领取已归来的探险”，默认关闭；核对居民释放后接续现有人员管理，未知结果跨刷新保留、不重复领取。发展规划计入外出居民回家后的供应需求；建造、升级和下挖只提供建议。

## 开发验证

需要 Node.js 24 和本机 Chrome / Edge，也可用 `CHROME_PATH` 指定浏览器。无需安装第三方依赖。

完整浏览器回归按顺序执行当前504项场景，总时限45分钟；各场景原有等待条件和断言保持不变。本版完整覆盖证据来自同一源码的四组互不重复的执行结果。

浏览器启动时在原15秒期限内等待调试端口文件可读且两行内容完整，处理Windows临时占用或文件尚未出现；其他文件错误仍立即报告。故障注入已验证占用、缺失及半写入状态后可正常连接浏览器。

```powershell
node --check .\arkengine-auto-encounter.user.js
node --test .\arkengine-stock-core.test.mjs .\arkengine-shelter-core.test.mjs
node --test .\arkengine-auto-encounter.test.mjs
```

发布新版时同步增加脚本版本、日志导出版本及对应测试断言，然后重新生成元数据文件：

```powershell
node -e 'const fs=require("node:fs");const s=fs.readFileSync("arkengine-auto-encounter.user.js","utf8");const h=s.match(/^\/\/ ==UserScript==[\s\S]*?\/\/ ==\/UserScript==/);if(!h)throw Error("Missing userscript metadata");fs.writeFileSync("arkengine-auto-encounter.meta.js",h[0]+"\n");'
```

验证通过且取得发布授权后，将安装脚本与元数据文件一起提交并推送到 `main`。仓库只包含脚本、说明和测试；本地运行日志及账户数据不应提交。


## 设计参考

本次借鉴以下项目的原则，使用浏览器原生 API 实现，不引入第三方运行依赖：

- [Playwright locators](https://github.com/microsoft/playwright/blob/83b80cfb2cc159fa2d3c4d9ee61803b55cdd06a5/docs/src/locators.md)：定位唯一当前目标，不任取首项。
- [idb](https://github.com/jakearchibald/idb/blob/654c746bef13f9fe7f5871e03ac58015cebace5a/README.md)：事务提交后确认写入，事务中不等待网络或其他外部任务。
- [TanStack Query retryer](https://github.com/TanStack/query/blob/2fb9d905f2184a32d998da657cfcc95c381014ad/packages/query-core/src/retryer.ts)：有限退避、离线等待与取消；本脚本继续支持后台执行。
- [XState](https://github.com/statelyai/xstate/tree/8f25b68f3953a9dd3c146a76f1f4972aba092a3f)：明确等待、暂停、未决操作和保存记录故障，隔离受影响功能。
